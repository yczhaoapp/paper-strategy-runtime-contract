# SX-CH-003 模糊标准与严格解释登记

本登记以公开题目 V2.1.0 为准。题目原文、评审附件和本项目说明的约束分开处理：题目决定最低门槛，附件提供失败案例，本项目采用更严格且可机器验证的解释。当前 Docker 严格验证已在本研究线完成，结论只以与输入树哈希绑定的收据为准。

| 模糊项 | 题目公开文字 | 本项目采用的严格标准 | 机器证据 |
| --- | --- | --- | --- |
| 18 个策略是否都必须来自论文 | 要求至少 18 个示例、三类各 6；背景强调从公开论文提取策略，但数量条款未明确要求 18 篇论文或 18 个完整复现 | 18 个策略全部一对一绑定论文来源、页级声明、代码哈希和测试；不要求 18 篇不同论文，至少 15 个不同来源；改变核心交易问题的样例明确标 A0 | `eighteen_strategy_bindings_with_fidelity_classification`；当前 15 个来源覆盖 18 个策略 |
| “论文复现”代表什么 | 未区分公式、方法、数据和实证结果 | 算法、数据、实验和运行时四轴独立；当前 14 个达到公式、算法或等价方法复现，4 个为方法适配；项目增强门禁保留 6 个公式和至少 9 个 A2，不以数量配额维持不准确标签 | `PaperStrategyBinding` 的 A/D/E/R 字段；当前 A2/A1/A0 为 9/5/4；`empirical_results_reproduced=false` |
| 论文页码和代码哈希是否足以证明落地 | 未规定论文声明与运行行为如何绑定 | 每个 claim 必须连接实现符号和精确测试节点；本轮 JUnit 必须证明节点已执行；输入、决策、动作、原因码和训练产物必须与审阅签名一致 | `claim_links`、`runtime_expectation` 与 18 个新生成 RunBundle |
| 是否必须真实行情 | 明确允许“公开样例数据或模拟行情数据”，脱敏说明再次允许自行生成模拟行情 | 同时提供公开历史与确定性合成两轨；18 个策略中规则、监督、RL 各至少两个 D1；另有一个深度案例在固定哈希的公开 OHLCV 上运行 | Donchian、Pairs Z-Score、Logistic、Ridge、A2C Pairs、线性 Actor–Critic 共六个 D1；Ma 案例另有 506 根公开 AAPL 日线；其余标记 D0 |
| 是否必须使用原论文数据 | 没有要求，且禁止依赖私有行情 | 原论文数据可得且许可清楚时优先；不可得时允许替代公开或合成数据，但必须声明 `original_paper_dataset=false` | 数据证据与论文报告共同校验 |
| 真实数据能否证明论文收益 | 题目只要求最小回测，没有要求重现实证表格 | 算法运行和实证复现分开；替代数据不得比较或宣称原论文收益、显著性和校准结论 | 所有复现规格固定 `empirical_results_reproduced=false` |
| “不同策略”如何判断 | 要求不同字段、粒度或动作，禁止参数复制 | 18 个算法 ID 独立；三类各 6；至少 12 种契约形状；每个策略必须有独立论文绑定并真实产生成交 | 策略指纹、运行报告和绑定覆盖门禁 |
| 规则策略是否需要训练 | 要求统一训练、推理、回测，但规则策略通常无模型拟合 | 统一生命周期中显式声明 `training=not_required`，仍执行初始化、因果 warm-up、推理和回测；监督与 RL 必须训练、保存、重载后推理 | 6 个规则无伪训练；12 个可训练策略各有内容寻址产物 |
| “真实回测引擎”指哪个引擎 | 未指定产品或最低数量 | 至少两个真实运行适配器通过能力协商和差分；仅有画像的引擎不得写成已验证 | Reference 与 Backtrader 为 `CONFORMANCE_VERIFIED`；LEAN/Qlib/vn.py 仅 `PROFILED` |
| 最小回测何时算成功 | 未规定必须成交或性能门槛 | 每个示例必须产生决策、订单和至少一笔成交；这只证明运行链路，不证明策略有效 | 18/18 报告的 fills > 0 |
| 自动化测试需要多完整 | 未给覆盖率或跳过上限 | 核心覆盖率至少 90%，验收测试 0 失败、0 错误、0 跳过；生成物必须无漂移 | JUnit、coverage.json、Schema/策略目录重生成比较 |
| 沙箱“支持或清晰设计”如何认定 | 安全条款同时出现“支持或清晰设计”和 S 档“有沙箱限制” | S 级按真实内核隔离解释；宿主静态扫描不能代替容器证明；环境不可用时必须失败 | `--require-strict` fail closed；当前 Linux/arm64 严格收据证明 18 个运行包均为 R2 |
| 兼容转换允许多自动 | 要求可追踪、可关闭、可审计，禁止隐藏 fallback | 默认关闭；每个转换有 ID、依据、损失性、字段、输入输出哈希和事件数量；未授权转换直接失败 | 兼容报告实际记录 10→2 事件 |
| 任意论文是否应自动生成代码 | 题目要求从不同论文/目录加载，没有要求开放域自主编程 | 内置自动编译只接受审阅 recipe 和受测后端；未知算法可由人或 LLM 形成结构化规格与独立实现，通过实际原文、页内证据、manifest、源码和运行门禁后执行，但仍要求人工审阅，不按标题选择近似策略 | `psrc author run`；三类未知规格黑盒测试；来源/锚点不符的导入前拒绝测试 |
| 公开数据的再分发权是否等于可下载 | 题目只要求公开样例，没有定义许可审计 | 保存来源 URL、内容哈希、仓库许可和权利说明；许可来源不完整时明确披露，不写成公共领域 | `data/public/source.json` 与原许可文本 |

这套解释有意把“数量达标”“论文忠实度”“数据真实性”“经验结论”和“运行时可接入性”拆成不同检查。任何一个维度的通过都不能自动提升其他维度。
