# 独立审计修复记录

本记录把公开题目要求、可复现反例和项目增强目标分开。修复优先级由运行契约的正确性决定，不由 Schema、覆盖率或自定义等级数量决定。

## 纳入本轮的发现

| 发现 | 独立判断 | 处理 |
| --- | --- | --- |
| Reference 接受策略未声明的动作 | 直接违反非法动作应明确失败 | 所有执行适配器统一调用规范动作验证；增加 Reference 负向回归 |
| 实际 payload 与 DatasetManifest 不一致仍成功 | 直接违反输入声明与实际运行一致性 | 运行前核对 kind、字段、标的、记录数、L2 深度和内容哈希；Contract v1 对无法归属的多流事件明确拒绝 |
| 改单绕过订单数量上限 | 直接违反动作限制 | `ReplaceOrder` 对修改后的最终数量重新执行限制检查 |
| IOC 被当作长期挂单 | 属于未披露的执行语义丢失 | Reference 仅声明并接受 `day`；其余 TIF 返回 `ORDER_REJECTED` |
| 线性 Actor–Critic 训练使用权重、推理使用股数 | 策略状态单位不一致 | 两条路径统一使用组合权重，并以共享一步更新函数做数值 oracle |
| A2C Pairs 的训练奖励、行为策略与执行组合不闭环 | 公式更新正确不足以支持论文交易方法复现 | 保留已验证的 A2C 更新和契约生命周期，整体降为 A0 方法适配并披露固定 spread、离线循环动作和 PnL 不一致 |
| 多笔直接订单可绕过总仓位、day 跨日成交 | 风险与订单有效期语义未完整执行 | 接单/改单/成交三重累计仓位校验；UTC/24×7 day 在下一 UTC 日撮合前过期 |
| 实际 bar 未核对声明时间网格 | 声明比较不能证明输入时间语义 | 对实际 `event_time` 执行 UTC/epoch 周期边界校验，同时允许缺 bar |
| 无效版本和复用输出目录形成非统一失败 | 结构化错误与产物一致性缺口 | SemVer Schema + 编译兜底；失败发布清除旧成功 Bundle 与运行产物 |
| 部分 A2 claim 仅连接运行成功测试 | 不满足项目自定的独立 oracle 标准 | 为 SMA、Donchian、Pairs、TWAP 增加手算/边界 oracle，并在绑定模型中强制 A2 指向独立复现测试 |
| ExecutionPlan 未绑定实际策略、Adapter 和沙箱 | 可形成归因错误或虚假严格模式的成功报告，属于公开运行契约缺陷 | 计划固定数据要求与最低沙箱；Adapter 暴露能力；orchestrator、RunReport 和 RunBundle 分层核对实际上下文 |
| lookback 与 max_staleness_ns 只声明未执行 | 文档强于实现，会让不满足数据要求的新策略错误通过 | 编译期检查 lookback 必要条件，转换后按标的执行；陈旧度固定为 available time 减 event time 并结构化失败 |
| 三个 A2 claim 的 oracle 未覆盖全部语义 | 不影响官方数量门槛，但不满足项目自身逐 claim 证据标准 | 增加 OHLCV 特征顺序、队列不平衡和推理边界 oracle；线性 Actor–Critic 因实质偏差降为 A1 |
| 直接调用 `BacktestAdapter.run` 可绕过 orchestrator 棚栏 | 公开回测入口能产生错误归因的成功报告 | Adapter 基类以不可覆写模板统一校验上下文、源事件、兼容转换和有效事件；引擎只实现已验证钩子 |
| 实际训练请求未与计划和产物绑定 | 可用另一份训练载荷生成模型后配上原证据 | 训练前重算证据哈希；产物记录训练请求哈希；orchestrator 与 `RunBundle` 分层核对 |
| 属性调用和宽泛 `psrc` 导入可绕过资源策略 | 与 `artifact_store_only` 声明冲突，策略可读容器文件、启动进程或篡改报告 | 只开放 `psrc.strategy_api`；别名/属性路径静态拒绝；导入和回调期审计围栏；模型写入只经不暴露根路径的能力对象；增加 NumPy、子进程和篡改反例 |
| 训练画像被错误要求由回测引擎提供 | 会拒绝本可运行的监督/RL 外部引擎生命周期 | 新增 `RuntimeCapabilities` 并固定能力分工与哈希；Backtrader 增加监督和 RL 全生命周期门禁 |
| Tabular Q、SARSA、Double Q 缺少方法级 oracle，且 Spooner 交易问题未保留 | 通用生命周期不能区分错误更新；正确更新也不能自动证明原论文做市策略 | 三种更新提取为独立步骤，增加多参数、terminal、零学习率、非贪心动作、双表交换、每种 64 组固定 seed 随机参考公式，并与完整生命周期共同绑定；生产源码另有无测试分支 AST 门禁；因动作和奖励已改变，三者如实降为 A0 方法适配 |
| 训练产物声明可伪造缺失文件或大小，ArtifactStore 根可被策略改写 | 成功报告可能没有真实模型，且策略可把受信 I/O 引向其他目录 | 存储根保留在主机授权表且不再把服务对象交给策略；训练后和加载后独立重读规范 manifest，核对路径、符号链接、文件、大小、哈希、策略身份和训练来源 |
| 策略仍可修改 `ArtifactStore` 类，或用带回调的 `str` 子类借用受信 I/O | 缺失模型可能被报告成功，审计豁免区可能执行策略代码 | 不再把主机 `ArtifactStore` 交给策略；每次运行创建独立 `ArtifactIO` 能力，先拒绝非内建类型，再调用未暴露的主机服务；加载必须产生受信字节读取记录；类修改、回调标量、缺失模型和空加载均纳入强制反例 |
| 策略返回延迟动作容器或在 `ArtifactManifest` 中注入可执行标量 | 回调结束后宿主迭代或校验这些对象会脱离资源围栏，并可能进入受信 I/O | manifest、动作和训练制品返回值在围栏内经 JSON 复制并按契约类型重建；延迟迭代器与制品标量子类反例进入强制验收 |
| 验收矩阵声明 18/0、程序实际执行 14/4 | `23/23` 可能被误读为验证了未执行的门槛 | 矩阵改为真实 14 个复现、最多 4 个适配；`PaperAcceptancePolicy` 严格解析全部阈值和深度论文 ID，catalog 与 paper verifier 只使用该对象；更严格的 15/3 矩阵回归必须失败 |
| Docker 客户端超时没有按容器 ID 清理 | CLI 超时后容器可能继续运行 | 每次严格运行使用随机容器名；超时后显式 `docker rm --force`，并在结构化错误中记录清理是否成功 |
| manifest 描述符和方法查找发生在资源围栏外 | 不可信属性访问可在回调前执行文件或进程副作用 | 本地包 manifest 读取和 `GuardedStrategy` 方法解析均移入同一资源围栏，只向后续组件暴露受信 manifest 快照 |
| Adapter 直接入口未完整核对字段/L2 深度，且可能泄漏原始异常 | 公开入口可绕过输入语义或产生非结构化失败 | 公共模板统一核对实际 payload 字段与深度，并把未知策略/引擎异常封装为 `BACKTEST_FAILED` |
| 目标动作可通过重复批次或派生订单绕过单笔上限 | 规范动作到原生订单的安全语义不闭合 | 每个标的每批只允许一个最终目标；Reference 与 Backtrader 在派生和成交边界再次核对数量和持仓 |
| 迟到 bar 按可用顺序选择 OHLC | 会记录并执行错误市场 bar | OHLC 按 `event_time, sequence` 聚合，可用/接收时间取最晚输入；重复市场时间明确拒绝 |
| Ridge 三日窗口与 L2 500ms 成交声明超过实现 | 论文绑定语义不可由旧实现支持 | Ridge 改为训练/推理一致的三个因果滞后收益；L2 限定 θ=0 常数率特例，以死亡计数/暴露时间估计强度并计算有限 500ms 竞速概率 |
| Backtrader 快照把真实持仓损益报告为零 | 统一账户输入错误，依赖止损、收益约束或奖励的策略会误判 | 累加 Backtrader 原生已平仓毛价格损益，并以当前可用收盘价标记浮动损益；用盈利、亏损、平仓、反向持仓和默认佣金样例回归 |
| 严格容器构建或启动失败保留上次成功收据 | 输出目录不能代表本轮执行，可能错误归因 | 启动即使旧收据失效；逐尝试目录隔离运行产物；构建、镜像检查、运行和缺收据均写失败；仅同一 `attempt_id` 的镜像与双收据成功时发布，证据发布器交叉核对 |
| 普通 `psrc run` 失败只输出 stdout | 不利于机器审计 | 所有普通运行失败写出 `FailureReport`、错误 JSON 和 HTML，尽可能保留已取得的上下文 |
| 没有固定提交和目标平台证据 | 属于交付闭环缺口 | 本轮建立本地不可变提交；远端仓库建立后由 CI 生成 Linux、Windows、macOS 和严格容器证据 |

## 未纳入本轮的扩张

- 不增加第三个默认引擎。题目需要扩展设计，两个真实引擎已经提供高于最低要求的证据。
- 不继续增加 D1 数量。当前三类各两个 D1；后续若改数据，应优先提高来源权威性和授权链。
- 不把 E0 提升为论文收益复现。题目要求最小回测，并未要求复现收益表或统计显著性。
- 不增加“任意论文自动生成代码”、生产实盘、D2/D3 或 E1/E2 范围。
- 不把 15 个来源、A2 数量和每类 D1 配额描述成官方 S 级要求。它们只作为项目增强结果披露。
- 不移除已隔离为可选 extra 且如实标注为未动态认证的 Nautilus Adapter；它不参与默认通过数量，保留它不削弱核心证据。

## 证据口径

18 个策略及三类各 6 个是题目硬要求。算法、数据、实验和运行环境使用 A/D/E/R 四轴披露，但这些等级是项目内部证据语言。任何 A2 都需要可定位论文声明、实现连接和独立公式或一步更新 oracle；行为哈希只证明结果没有漂移，不能单独证明算法正确。
