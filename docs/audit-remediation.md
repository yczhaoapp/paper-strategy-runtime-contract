# 独立审计修复记录

本记录把公开题目要求、可复现反例和项目增强目标分开。修复优先级由运行契约的正确性决定，不由 Schema、覆盖率或自定义等级数量决定。

## 纳入本轮的发现

| 发现 | 独立判断 | 处理 |
| --- | --- | --- |
| Reference 接受策略未声明的动作 | 直接违反非法动作应明确失败 | 所有执行适配器统一调用规范动作验证；增加 Reference 负向回归 |
| 实际 payload 与 DatasetManifest 不一致仍成功 | 直接违反输入声明与实际运行一致性 | 运行前核对 kind、字段、标的、记录数、L2 深度和内容哈希；Contract v1 对无法归属的多流事件明确拒绝 |
| 改单绕过订单数量上限 | 直接违反动作限制 | `ReplaceOrder` 对修改后的最终数量重新执行限制检查 |
| IOC 被当作长期挂单 | 属于未披露的执行语义丢失 | Reference 仅声明并接受 `day`；其余 TIF 返回 `ORDER_REJECTED` |
| 线性 Actor–Critic 训练使用权重、推理使用股数 | 策略状态单位不一致 | 两条路径统一使用组合权重，并以共享一步更新函数做数值 oracle |
| A2C Pairs 的滚动回归声明与固定 1:-2 spread 不符 | 证据不足以支持 A2 | 保留已验证的 A2C 更新，但整体降为 A1 等价方法复现并披露固定 spread 偏差 |
| 普通 `psrc run` 失败只输出 stdout | 不利于机器审计 | 所有普通运行失败写出 `FailureReport`、错误 JSON 和 HTML，尽可能保留已取得的上下文 |
| 没有固定提交和目标平台证据 | 属于交付闭环缺口 | 本轮建立本地不可变提交；远端仓库建立后由 CI 生成 Linux、Windows、macOS 和严格容器证据 |

## 未纳入本轮的扩张

- 不增加第三个默认引擎。题目需要扩展设计，两个真实引擎已经提供高于最低要求的证据。
- 不继续增加 D1 数量。当前三类各两个 D1；后续若改数据，应优先提高来源权威性和授权链。
- 不把 E0 提升为论文收益复现。题目要求最小回测，并未要求复现收益表或统计显著性。
- 不增加“任意论文自动生成代码”、生产实盘、D2/D3 或 E1/E2 范围。
- 不把 15 个来源、A2 数量和每类 D1 配额描述成官方 S 级要求。它们只作为项目增强结果披露。

## 证据口径

18 个策略及三类各 6 个是题目硬要求。算法、数据、实验和运行环境使用 A/D/E/R 四轴披露，但这些等级是项目内部证据语言。任何 A2 都需要可定位论文声明、实现连接和独立公式或一步更新 oracle；行为哈希只证明结果没有漂移，不能单独证明算法正确。
