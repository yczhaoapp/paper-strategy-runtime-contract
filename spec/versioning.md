# 版本规则

Contract 遵循语义化版本。任何不兼容的 Schema 或生命周期变更都必须升级 major 版本。Minor 版本可以增加可选字段、新错误码、新能力标识符或新的可判别联合类型分支。Patch 版本只能澄清文档或修正不改变已接受文档集合的实现缺陷。

每份公开 Schema 都有稳定 `$id`。策略、数据集、引擎、产物、执行计划、错误和报告文档保留验证它们的 Contract 版本。主版本不匹配时，必须在 import 策略代码前拒绝。

中文文档与英文机器标识符是两个独立层次。翻译说明文字不改变 Contract 版本；修改字段名、枚举值、必填性或线格式则按上述兼容性规则升级版本。

`1.1.0` 仅增加可选源码证据字段、新错误码和新转换标识符。`1.0.0` 的执行计划即使没有源码证据字段，仍可由 `1.1.0` 模型解析；编译器继续接受同一 major 的 `1.0.0` 策略、数据集和引擎声明。当前验证器可以对新生成物提出更高要求，但这不会追溯改变 `v1.0.0` Schema 所接受的文档集合。
